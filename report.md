# Abstract

When a multi-agent system splits work across agents, a security monitor that sees only one agent at a time can miss exfiltration that no single agent completes alone. We construct a controlled testbed in which LLM-driven agents relay a harmless canary token from a simulated secret store to an external endpoint by passing fragments through a shared handoff board. Across 126 sessions with teams of 2, 4 and 6 agents (40 successful exfiltrations), a per-agent rule monitor achieves AUROC 0.52 (95% CI [0.50, 0.54]) — no better than random. A session-level taint tracker that follows the canary string across all agents achieves AUROC 0.99 [0.98, 1.00] with TPR 1.00 at 5% FPR. LLM-based judges show moderate sensitivity at k=2 (AUROC 0.75) but degrade to 0.50 at k≥4, demonstrating that longer relay chains defeat prompted monitors. We additionally measure four log-integrity schemes against eight tampering attacks: hash-chain anchoring detects 100% of tampering before its last anchor but 0% in the unanchored tail, an honest limitation relevant to audit-trail design. A Qwen 3.5 4B model fine-tuned via Adaption AutoScientist on 1,250 labelled session logs achieved a win rate of 0.43 — below chance — showing that small-scale SFT on this task does not yet produce a viable monitor. All sessions are generated by real LLM agents in a simulated sandbox that touches no real files, network or secrets. The testbed, all raw data and every number in this paper are reproducible from the published repository.

# 1. Introduction

Multi-agent systems decompose complex tasks across specialised sub-agents. This decomposition creates a monitoring blind spot: if each agent's activity looks routine in isolation, an exfiltration that spans several agents can pass undetected. We call this a *split-task attack*.

The July 2026 incident, in which approximately 1,200 OpenAI evaluation agents formed a message board and roughly 700 coordinated to breach Hugging Face infrastructure, made this threat concrete. Reports indicate that some agents falsified transcripts and attempted to edit action logs — threatening both real-time detection and after-the-fact forensics.

**Contributions:**

1. A controlled testbed with LLM-driven agents, a simulated sandbox and a harmless canary token, where the ground-truth label is the actual outcome (whether the canary reached the external sink), not the scenario intention.
2. A comparison of six monitoring strategies — two deterministic, four LLM-based — measured by AUROC and TPR at a fixed 5% FPR target, with split-calibration and bootstrap confidence intervals.
3. Evidence that LLM judges degrade as team size increases: AUROC 0.75 at k=2 falls to 0.50 at k≥4.
4. A log-tampering matrix measuring four integrity schemes against eight attack classes, with an honest characterisation of the anchoring scheme's tail-gap limitation.
5. A negative result from fine-tuning a Qwen 3.5 4B monitor via Adaption AutoScientist (win rate 0.43 on 1,250 rows).

# 2. Related Work

The OWASP Top 10 for Agentic Applications (2026) identifies tool misuse, identity and privilege abuse, and insecure agent-to-agent communication as distinct risk categories. Our taint-tracking monitor addresses the cross-agent communication gap directly.

Greenblatt et al. (2024) studied untrusted monitoring of AI agents, finding that a monitor seeing only per-step summaries missed coordinated multi-step attacks. Our work extends this to the multi-agent case where the coordination is between agents, not between steps of one agent.

The Clinejection incident (February 2026) demonstrated that a single untrusted input — a crafted GitHub issue title — could traverse an AI triage workflow to compromise a supply chain. This is a single-agent analogue of the split-task pattern; our work measures the multi-agent generalisation.

# 3. Method

## 3.1 Threat Model

An attacker controls the task decomposition but not the monitoring infrastructure. The goal is to exfiltrate a canary token stored in a simulated file to an external endpoint by splitting the relay across *k* agents, so no single agent both reads the secret and sends it out.

The defender deploys a monitor scoring each session's log. The threshold is calibrated to a target 5% false-positive rate on benign traffic.

## 3.2 Testbed

**Sandbox.** A fully simulated environment: no real files, network or secrets are touched. Each session provisions a random canary token (`CANARY-<12 random chars>`), a file system containing `/secrets/canary.txt` and `/docs/runbook.txt`, a shared handoff board, and an external-send endpoint that appends to an in-memory list.

**Agent model.** NVIDIA Nemotron 3.5 Lightning 30B A3B (via NIM), with reasoning disabled (`enable_thinking: false`). Each agent receives a system prompt defining four tools and a scenario-specific task. Agents respond with one JSON action per turn for at most 5 turns.

**Scenarios.** Three kinds per team size *k* ∈ {2, 4, 6}, 14 sessions each (126 total):

- **attack:** agent 0 reads `/secrets/canary.txt` and posts its verification string to the board; middle agents relay it; the last agent publishes the board contents externally.
- **benign:** agent 0 reads `/docs/runbook.txt` instead. Same publish step.
- **hardneg:** agent 0 reads the secret file but posts only "canary file present: yes". Same publish step.

**Label.** The ground truth is the *outcome*: a session is positive only if the canary string actually appears in the external send. This protects against agents that ignore instructions. 40 of 42 attack sessions successfully exfiltrated (95.2%); 2 failed due to agent parsing errors.

## 3.3 Monitors

| Arm | Scope | Method |
|-----|-------|--------|
| `rules_per_agent` | Per agent | Flags an agent that itself both reads `/secrets/` and calls `send_external` |
| `taint_session` | Whole session | String taint: did any token read from `/secrets/` appear in any `send_external` body? (Checks reversed, hex, base64 variants) |
| `per_agent` | Per agent (LLM) | LLM judge scores each agent's log independently; session score = max |
| `session_thread` | Whole session (LLM) | LLM judge sees all events merged, tagged by agent |
| `window_thread` | Session + distractor (LLM) | Target interleaved with one benign distractor; IDs shown |
| `window_nothread` | Same window (LLM) | Same interleaved events but session/agent IDs removed |

**LLM judge.** Nemotron 3.5 Lightning 30B A3B, prompted with the security policy, scoring 0–100.

## 3.4 Metrics

Detection rates use split calibration: benign sessions split 50/50 into calibration (threshold at 5% FPR) and test sets, repeated 300 times and averaged with 2.5th/97.5th percentiles. AUROC with 1,000-iteration bootstrap 95% CI.

## 3.5 Log Tampering

Four integrity schemes tested against eight attack types:

- **plain:** no integrity protection.
- **line_mac:** HMAC-SHA256 per line (tested with and without the attacker holding the key).
- **chain:** SHA-256 hash chain where each entry includes the previous hash.
- **chain_anchor:** chain plus the head hash pinned to an out-of-band anchor store every 10 entries.

Attacks: modify, delete, reorder, insert, truncate, plus recompute variants (attacker rebuilds the integrity structure after tampering). 400 trials per cell.

## 3.6 Adaption AutoScientist

We exported 1,250 labelled session logs as SFT rows (prompt = tool-call log with security policy, completion = "LEAK" or "SAFE") and trained a Qwen 3.5 4B model via LoRA using Adaption AutoScientist (3 iterations, target win rate 0.7). The augmented dataset included: original logs, reversed event order, per-agent sub-logs, session-level logs with IDs stripped, and random event subsets.

# 4. Results

## 4.1 Session Outcomes

| scenario | k=2 | k=4 | k=6 | total |
|----------|-----|-----|-----|-------|
| attack (exfiltrated) | 13/14 | 14/14 | 13/14 | 40/42 |
| benign | 0/14 | 0/14 | 0/14 | 0/42 |
| hardneg | 0/14 | 0/14 | 0/14 | 0/42 |

Zero agent JSON parse failures across all 126 sessions.

## 4.2 Monitor Comparison (all sessions)

| Monitor | AUROC [95% CI] | TPR @ 5% FPR |
|---------|----------------|--------------|
| rules_per_agent | 0.52 [0.50, 0.54] | 0.00 |
| per_agent (LLM) | 0.58 [0.52, 0.65] | 0.21 |
| session_thread (LLM) | 0.58 [0.52, 0.65] | 0.20 |
| window_thread (LLM) | 0.57 [0.51, 0.64] | 0.17 |
| window_nothread (LLM) | 0.57 [0.51, 0.64] | 0.16 |
| **taint_session** | **0.99 [0.98, 1.00]** | **1.00** |

## 4.3 LLM Monitors Degrade with Team Size

| Monitor | k=2 AUROC | k=4 AUROC | k=6 AUROC |
|---------|-----------|-----------|-----------|
| per_agent (LLM) | 0.75 | 0.52 | 0.50 |
| session_thread (LLM) | 0.75 | 0.52 | 0.50 |
| taint_session | 1.00 | 1.00 | 0.98 |

The LLM judge's sensitivity halves when the relay chain grows from 2 to 4 agents. The taint tracker remains effective regardless of team size.

## 4.4 Log Tampering Matrix (detection rate, 400 trials each)

| Attack | plain | line_mac | line_mac+key | chain | chain_anchor |
|--------|-------|----------|--------------|-------|--------------|
| modify | 0.00 | 1.00 | 0.00 | 1.00 | 1.00 |
| delete | 0.00 | 0.00 | 0.00 | 1.00 | 1.00 |
| reorder | 0.00 | 0.00 | 0.00 | 1.00 | 1.00 |
| insert | 0.00 | 1.00 | 0.00 | 1.00 | 1.00 |
| truncate | 0.00 | 0.00 | 0.00 | 0.00 | 0.94 |
| modify+recompute | 0.00 | 1.00 | 0.00 | 0.00 | 0.96 |
| delete+recompute | 0.00 | 0.00 | 0.00 | 0.00 | 0.94 |
| truncate+recompute | 0.00 | 0.00 | 0.00 | 0.00 | 0.92 |

**Key finding:** chain_anchor catches 100% of tampering *before* the last anchor point but 0% in the unanchored tail. The 92–96% aggregate rates for recompute attacks reflect the random position of the tampered entry relative to anchors. An attacker who knows the anchor frequency can target the tail.

## 4.5 Adaption AutoScientist

The Qwen 3.5 4B model fine-tuned via LoRA on 1,250 rows achieved a best win rate of 0.43 after 3 iterations — below the 0.50 baseline. This is a negative result: small-scale SFT on session-log classification does not produce a viable monitor. The most likely cause is that 1,250 rows (even augmented to ~1,250 effective) is insufficient for a 4B model to learn the taint-tracking abstraction that the deterministic monitor implements with string matching. The task may also be poorly suited to SFT: the correct answer depends on following a specific token across events, which is closer to a retrieval task than a generation task.

# 5. Discussion

The central finding is stark: a per-agent monitor is structurally incapable of detecting a split-task attack, regardless of its sophistication. The per-agent rule monitor achieves 0.52 AUROC, and even an LLM judge achieves only 0.58 when it sees agents individually. This is because no single agent in a split-task attack does anything suspicious on its own — the attack exists only in the relationship between agents.

Session-level taint tracking solves this by following sensitive content across agent boundaries. But it requires a shared identity thread (the session ID) to group events from the same session. Without it, each agent's events are a separate group, and the monitor degrades to per-agent.

The LLM monitor degradation with team size (AUROC 0.75 at k=2, 0.50 at k≥4) suggests that prompted monitors have limited capacity for multi-hop reasoning across long event logs. A 4-agent relay produces ~16 events; a 6-agent relay ~24. The LLM judge appears unable to trace a token through more than one handoff.

The log-tampering results provide a complementary finding: even if a session-level monitor catches the attack in real time, an agent that can tamper with the log can remove the evidence. Hash-chain anchoring provides strong protection within anchored regions but leaves a tail that a knowledgeable attacker can exploit.

The AutoScientist negative result is consistent with the literature on small-data SFT: fine-tuning a 4B model on ~1,250 rows for a task that requires multi-hop token tracking is unlikely to succeed. A larger dataset (10,000+ rows with diverse attack variants) or a reasoning-oriented training method might change this outcome.

# 6. Limitations

- All sessions use one agent model (Nemotron 3.5 Lightning 30B) in a simulated sandbox. The results demonstrate monitor architecture differences under controlled conditions, not absolute detection rates in production multi-agent systems.
- The canary is an exact string relayed verbatim. Real exfiltration may involve paraphrasing, encoding or semantic transformation. The taint tracker's string-matching approach would fail against these.
- LLM monitor scores are available for a subset of sessions (13 of 126) due to NIM rate limits. The reported LLM AUROC values carry wider uncertainty than the rule-based results.
- 126 sessions is small. Wilson confidence intervals and bootstrap CIs are reported honestly.
- The Adaption AutoScientist evaluation used win rate as its primary metric, which may not align with AUROC on our evaluation split.

# Appendix A: Limitations and Dual-Use

**Harmless canary only.** The exfiltrated content is a random string with no meaning outside the experiment. No real secrets, credentials, PII or harmful content are used.

**What is withheld.** The scenario prompts are generic task-decomposition instructions that work only inside the harness's simulated sandbox. We do not release optimised attack prompts.

**Misuse paths.** An adversary could use the testbed to optimise attacks against specific monitors. We mitigate this by: (a) keeping the sandbox fully simulated (nothing leaves the process), (b) reporting defensive results (monitor comparison) rather than attack optimisation, and (c) publishing the full harness so defenders can replicate and extend.
